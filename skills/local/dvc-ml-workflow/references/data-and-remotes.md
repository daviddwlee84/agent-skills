# Data, models, and remote storage

> Authoritative source: https://dvc.org/doc/user-guide/data-management and https://dvc.org/doc/command-reference/remote

## `dvc add` vs pipeline outputs

| Use `dvc add` for | Use pipeline `outs` for |
|---|---|
| Raw input data that is not produced by code | Anything generated by a stage |
| Pre-trained models you downloaded | Models you train in a stage |
| Static reference datasets | Intermediate features |

Files tracked by `dvc add` get a sibling `.dvc` pointer file that **must** be committed to git:

```bash
dvc add data/raw/
ls -la data/
# data/raw/        ← actual data, gitignored automatically
# data/raw.dvc     ← tiny pointer, must `git add`
# data/.gitignore  ← also created/updated, must `git add`
```

## Remote storage backends

DVC supports many backends; the package install determines which:

```bash
pip install 'dvc[s3]'            # AWS S3 (also works with MinIO, Wasabi, R2)
pip install 'dvc[gs]'            # Google Cloud Storage
pip install 'dvc[azure]'         # Azure Blob
pip install 'dvc[ssh]'           # SSH/SFTP
pip install 'dvc[gdrive]'        # Google Drive
pip install 'dvc[oss]'           # Alibaba OSS
pip install 'dvc[webdav]'        # WebDAV
pip install 'dvc[all]'           # everything
```

For S3-compatible (MinIO, Cloudflare R2, Wasabi):

```bash
dvc remote add -d minio s3://my-bucket/path
dvc remote modify minio endpointurl http://minio.local:9000
dvc remote modify --local minio access_key_id $MINIO_KEY
dvc remote modify --local minio secret_access_key $MINIO_SECRET
```

The `--local` flag stores the credential in `.dvc/config.local` (gitignored). Without it, the credential goes to `.dvc/config` (committed) — **never do that for secrets**.

## Setup recipes

### AWS S3 (with profile)

```bash
dvc remote add -d s3remote s3://my-bucket/dvc-store
dvc remote modify s3remote profile my-aws-profile
# OR rely on AWS_PROFILE env var
```

### Google Cloud Storage (with service account)

```bash
dvc remote add -d gs gs://my-bucket/dvc-store
dvc remote modify --local gs credentialpath /path/to/sa.json
```

### Google Drive (OAuth)

```bash
dvc remote add -d gdrive gdrive://<folder-id>
# First push triggers a browser OAuth flow.
# For headless: dvc remote modify --local gdrive gdrive_use_service_account true
```

### SSH / SFTP

```bash
dvc remote add -d ssh ssh://user@host/path/to/dvc-store
dvc remote modify ssh port 22
dvc remote modify --local ssh keyfile ~/.ssh/id_rsa
```

### MinIO (self-hosted S3)

```bash
dvc remote add -d minio s3://mlflow/dvc-store
dvc remote modify minio endpointurl http://localhost:9000
dvc remote modify minio use_ssl false
dvc remote modify --local minio access_key_id minioadmin
dvc remote modify --local minio secret_access_key minioadmin
```

## Push / pull / fetch

```bash
dvc push                              # upload missing cache → remote
dvc push -r <remote-name>             # to a non-default remote
dvc push -j 8                         # 8 parallel uploads

dvc fetch                             # download missing cache from remote (no checkout)
dvc pull                              # fetch + checkout (i.e., materialize files)
dvc pull <file>                       # pull only what's needed for a single file

dvc status -c                         # cloud status: which files differ from remote
```

`dvc pull` is what collaborators run after `git clone` to get the actual data.

## Multiple remotes (e.g., dev + prod)

```bash
dvc remote add s3-dev  s3://dev-bucket/dvc
dvc remote add s3-prod s3://prod-bucket/dvc
dvc remote default s3-dev               # set default

dvc push -r s3-prod                     # explicit remote for one push
```

## Importing data from another DVC repo or git repo

```bash
dvc import https://github.com/example/data-repo data/imagenet
# Records the source repo + commit; later `dvc update` re-fetches.

dvc import-url https://example.com/big.tar.gz data/big.tar.gz
# Pin a URL as a tracked dependency.
```

## Common pitfalls

- **`dvc push` reports 0 files but no error** — Cache is empty (nothing to push) OR remote credential is missing for a backend that fails silently. Always run `dvc status -c` after the first push.
- **`Permission denied` on `dvc pull`** — Credential not set for the current user. Re-run `dvc remote modify --local`.
- **`.dvc/config` accidentally contains a secret** — `git rm --cached .dvc/config && git commit`, then re-add the remote with `--local`. Rotate the secret if it was pushed.
- **Cache grows unbounded** — `dvc gc --workspace` removes cache entries not in the current workspace. Use `--all-branches --all-tags` to also keep history. **Run `dvc push` BEFORE `dvc gc`** or you'll lose the only copy of artifacts not yet on the remote.
- **`dvc add` on a file inside a stage's `outs`** — Confuses DVC. Pick one tracking method: either it's a stage output (managed by `dvc.yaml`) or a manual artifact (managed by `dvc add`), never both.
- **Symlinks, reflinks, hardlinks**: by default DVC reflinks (CoW on APFS/Btrfs/XFS) or copies. To save disk on huge datasets: `dvc config cache.type "reflink,hardlink,symlink,copy"`. Symlinks are fastest but read-only.

## Verifying remote setup quickly

```bash
echo "test" > /tmp/dvc-test.txt
dvc add /tmp/dvc-test.txt              # adds to local cache
dvc push                                # upload
dvc status -c                           # should show "Cache and remote are in sync"
```

If `dvc status -c` reports anything other than "in sync", the remote is misconfigured.
